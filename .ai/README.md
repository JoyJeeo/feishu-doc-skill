# AI 产品资料入口

本目录保存 `feishu-doc-skill` 的产品基线、稳定决策和迭代路线。它面向后续参与设计、实现和评审的 AI 与开发者，不是运行时代码。

## 当前阶段

- 已完成里程碑：M0 产品基线、M1 安全执行闭环
- 当前里程碑：M2 飞书文档（进行中）
- 当前进度：`SPEC-M2-01` 已完成；`SPEC-M2-02` 已实现并生成真实目标预览，等待用户人工验收
- 产品形态：个人版飞书云文档 Skill
- 远端能力：仅使用已经连接的飞书 MCP
- 目标平台：飞书中国版

## 阅读顺序

1. [DECISIONS.md](DECISIONS.md)：先了解不可绕过的产品和安全决策。
2. [PRODUCT.md](PRODUCT.md)：理解完整产品范围、功能效果和验收标准。
3. [ROADMAP.md](ROADMAP.md)：确认当前阶段、实施顺序和退出条件。
4. 阅读仓库现有实现，核对实现与产品资料是否一致。

信息冲突时，按以下优先级处理：

```text
用户当前明确要求
> DECISIONS.md 中状态为“生效”的决策
> PRODUCT.md 产品设计
> ROADMAP.md 迭代安排
> 历史实现行为
```

发现冲突时不得自行选择，应停止受影响的工作并向用户说明。

## 不可绕过的执行边界

- 飞书资源的读取、创建、修改、删除、移动、评论、权限、导入和导出，只能通过飞书 MCP 完成。
- 默认使用用户身份；不得因权限不足或调用失败自动降级到应用身份。
- 用户未明确要求时，不得调用 Chrome、浏览器自动化、CUA、其他连接器或直接 HTTP 请求操作飞书。
- MCP 没有提供所需能力时，只报告不支持，不寻找替代通道。
- 所有远端写入必须先生成预览，再获得用户对该预览的明确确认。
- 删除、转移所有者和公开权限修改默认关闭。

上述规则必须在后续 `SKILL.md` 和对应工作流中再次编码；仅存在于 `.ai` 文档中不能形成运行时保障。

## 维护规则

- 稳定边界或关键取舍变化时，先更新 `DECISIONS.md`，再同步其他文档。
- 新增产品能力时，在 `PRODUCT.md` 中说明功能、实现效果、原因、依赖和验收方法。
- 只有验收通过后，才能在 `ROADMAP.md` 中将里程碑或功能标记为“已完成”。
- MCP 工具清单只是环境快照，不应被当作永久接口承诺；实施时仍需检查工具是否可见。
- 不在 `.ai` 中保存访问凭证、文档 Token、用户 ID、租户信息或敏感正文。
- 不为了保持文档完整而虚构尚未确认的飞书能力。

## 进入实现前检查

- 已阅读全部生效决策。
- 用户已授权对应里程碑。
- 计划修改的文件和验收方法已经明确。
- 所需飞书 MCP 工具可见。
- 若涉及真实飞书资源，已获得目标资源及相应只读授权。
- 若涉及远端写入，已经生成本次操作的预览；此前的里程碑授权不能代替单次写入确认。
